# 已知问题与待优化项

日期：2026-11-17

## 已修复

### 1. 保存窗口错误地退化为文件夹选择器

**现象**：下载时弹出的是「选择文件夹」窗口，且路径框里自动填了
`歌名 - 歌手`，确认后提示「所选文件夹不存在」。

**根因**：调用 `showSaveDialog` 时传了 `canSelectFolder: true`。
宿主实现（`desktop/src/renderer/winMain/main.ts`）在该分支下改用
`dialog.showOpenDialog({ properties: ['openDirectory', 'createDirectory'] })`，
此时 `defaultFileName` 被当作 `defaultPath`，即「要进入的目录」，
而该目录并不存在。

此外 `writeSaveBoxFile(dir, name, content)` 的第一参数在 `saveDirs` 缓存中
查的是**目录**，拿到完整文件路径会查不到。

**修复**：去掉 `canSelectFolder`，改用真正的「另存为」文件窗口。
该模式返回完整文件路径，写入时 `name` 传空串，worker 会直接用该路径落盘。
完成提示显示的是**实际保存的文件名**（用户可能在对话框里改名）。

验证输出：

```
["saveDialog","canSelectFolder=false","晴天 (原唱 周杰伦) - RyaVocal.flac"]
dirArg : D:/.../晴天 - Jay.mp3   <- 完整文件路径
nameArg: ""                       <- 空串
```

## 待优化（非优先级）

### 2. 下载窗口弹出偏慢

**实测耗时分布**（从命令触发开始计时，单次下载）：

| 阶段 | 累计耗时 | 占比 |
|---|---|---|
| 读取配置 | 1 ms | ~0% |
| 输入对话框 | 203 ms | 15% |
| **搜索请求** | 1142 ms | **85%** |
| 候选对话框 | 1346 ms | — |
| 保存对话框 | 1346 ms | — |
| 写入文件 | 1346 ms | — |

**结论**：瓶颈是**搜索网络请求**（约 1.1 秒），不是扩展代码本身。
用户感知的「下载窗口弹出慢」实际是「输入后等待候选列表出现的时间」。

**可选优化方向**（按性价比排序）：

1. **搜索期间给出即时反馈**：在发起请求前先关闭输入框并显示
   「正在搜索…」提示，避免用户面对静止界面。成本低，感知提升明显。
   注：`showMessage` 是模态的，需确认能否用非模态方式提示。
2. **减少候选数量**：当前请求 `count=20`，改为 10 可略微缩短响应。
   但服务端耗时占主导，收益有限。
3. **缓存搜索结果**：同一关键词短时间内重复搜索可复用。
   实际用户很少重复搜同一首歌，收益低。
4. **并发预取**：在用户看候选列表时预取前几条的音频 URL。
   可省掉点击后的等待，但会浪费带宽（用户可能不选第一条）。

**建议**：优先做方向 1。其余方向需实测确认收益后再决定。

### 3. API 间歇性 503

聚合 API 在短时间内多次请求后会返回 Cloudflare 503。
当前实现已有 3 次重试（1s / 2s 退避），但若用户在几分钟内连续下载多首，
仍可能遇到多次失败。

可选缓解：延长退避时间、或在错误提示中建议稍后再试。暂不处理。
